# Leakage-safe weekly HPAI risk mapping in Japan — reproducibility package

This repository accompanies the Preventive Veterinary Medicine manuscript on leakage-safe weekly HPAI risk mapping in Japan. It documents the analysis lineage used for the reported manuscript results, preserves the reported numerical outputs, and provides code to verify those results.

## Reproducibility status

### Strict first-occurrence-like analysis
The executed notebook `code/04_strict_event_evaluation/14_v7_strict_baseline_vs_gis.ipynb` is the primary strict-event analysis used for the reported baseline-versus-GIS comparison. Its archived outputs reproduce the manuscript values, including:

- baseline Top 10% capture: 11/49 = 22.4%
- GIS Top 10% capture: 19/49 = 38.8%
- absolute difference: +16.3 percentage points
- paired-bootstrap 95% CI: +2.0 to +30.6 percentage points
- Top 10% transitions: 12 gain, 4 loss, 7 stable success, 26 stable miss
- two-sided exact binomial test: p = 0.0768

### Rolling fiscal-year evaluation
The original notebook recorded as `06_v2_rolling_riskmap_evaluation_previous_week_weather_final` could not be located during the repository audit. However, the archived 12 split/model prediction parquet files, fitted model files, split definitions, feature-set definitions, summaries, and validation outputs are preserved.

`code/03_rolling_evaluation/06_v2_FAST_VERIFY_and_OPTIONAL_RETRAIN.ipynb` independently recomputes the rolling event-level metrics from the archived prediction files and validates them against both the archived summary and the manuscript Table 2 values. This verification was run successfully on 19 September 2026 and returned:

`SUCCESS — ARCHIVED 06_v2 PREDICTIONS REPRODUCE THE MANUSCRIPT TABLE 2 VALUES.`

The same notebook also contains a documented optional full-retraining implementation. Full refitting is disabled by default because it fits 12 Random Forest models on approximately 0.74–1.32 million grid-week rows per fiscal-year split and can require substantial CPU time.

## Repository structure

- `code/01_data_preparation/` — weather/panel preparation notebooks relevant to the reported analysis.
- `code/02_gis_landuse/` — GIS and historical land-use feature construction used by the reported analysis.
- `code/03_rolling_evaluation/` — archived-output verification plus documented optional full Random Forest refitting.
- `code/04_strict_event_evaluation/` — primary strict Extra Trees analysis and first-occurrence sensitivity analysis.
- `code/05_figures/` — Figure 1–6 and Supplementary Figure S1 generation notebooks.
- `reported_outputs/` — small archived output tables supporting the reported manuscript values.
- `audit/` — provenance, validation, exclusion, and known-issue notes.
- `revision_text/` — draft text for the second-round reviewer response and manuscript amendments.

## Recommended execution order

For verification of the reported results, the recommended order is:

1. Run `code/03_rolling_evaluation/06_v2_FAST_VERIFY_and_OPTIONAL_RETRAIN.ipynb` with `RUN_FULL_RETRAIN = False`.
2. Inspect/run `code/04_strict_event_evaluation/14_v7_strict_baseline_vs_gis.ipynb` using the frozen processed inputs used for the reported analysis.
3. Run `code/04_strict_event_evaluation/14_v13_sensitivity_analysis.ipynb` to reproduce the alternative first-occurrence definitions from the saved strict-event predictions.
4. Run the figure notebooks in `code/05_figures/` using the archived output files.

## Historical land-use preprocessing note

The reported analysis used the historical processed feature set generated by the `18_v8` workflow. A later audit found that a source-file processing cap caused only 60 of 135 unique land-use tiles to be represented before the cap was reached. Consequently, the five local land-use composition indicators were available in the processed feature set for 4,095 of 5,491 grid cells. A later full-unique-tile rebuild increased availability to 4,512 grid cells.

The manuscript therefore describes the 1,396 missing grid cells specifically as missingness in the **processed feature set used for the reported analysis**, not as proof that the underlying source land-use data were absent. The later corrected full-tile analysis is not substituted for the historical input in this repository because it did not generate the submitted manuscript values.

## Public source data

The study uses publicly available outbreak, meteorological, geographic, elevation, and land-use sources described in the manuscript. Large processed inputs are not included in this GitHub package. Before archiving processed inputs in Zenodo or another repository, confirm redistribution terms for each derived source dataset. The code retains the expected Google Drive path structure used during the analysis; users may adapt paths to their local environment.

## Large archived predictions and fitted models

The original rolling evaluation produced 12 prediction parquet files and 12 fitted Random Forest model files. These are not required for source-code inspection but are required for the fastest exact validation of the reported rolling metrics. For a permanent release, place these large archived artifacts in a versioned data archive (for example Zenodo) and reference the DOI from this repository.

## Provenance and later diagnostics

Later diagnostic/reanalysis notebooks (`14_v9_*`, later full-tile GIS rebuilds, `FINAL_MASTER_REANALYSIS_V2`, and training-identity experiments) were useful for auditing the workflow but are **not** the source of the numerical results reported in the manuscript. They are intentionally excluded from the primary reproducibility package. See `audit/PUBLISH_EXCLUDE_LIST.md`.
